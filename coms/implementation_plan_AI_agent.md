# Exploring Agentic AI in the Assessment Hub

This plan explores how **Agentic AI**—artificial intelligence that can make decisions, use tools, and act autonomously within given boundaries—can transform the Assessment Hub from a static platform into a dynamic, intelligent evaluator.

## 1. Opportunities for Agentic AI Integration

Based on our current system (ProctoredCodeEditor, FastAPI backend, React frontend), Agentic AI can operate autonomously in the following domains:

### A. Dynamic Follow-Up Interviewer (The "Agentic Examiner")
- **Concept:** After a candidate submits their code or completes a skill test, the Agentic AI reviews their specific submission and autonomously generates follow-up questions to assess deep understanding (e.g., "I noticed you used a nested loop here making it $O(n^2)$. Can you think of an approach using a Hash Map?").
- **Agent Action:** The agent waits for the candidate's chat response, evaluates it, and scores their semantic understanding, feeding this into the final assessment report.

### B. Contextual Proctoring Agent
- **Concept:** Currently, proctoring is rule-based (e.g., BlazeFace detects 2 faces `->` Critical Violation). An Agentic AI can handle proctoring anomalies gracefully.
- **Agent Action:** If a phone is detected or tab is switched, the Agentic AI can pause the test and interact with the user via a modal (e.g., "I noticed you switched tabs to look at documentation. Be aware this task is closed-book. Please confirm you have closed the documentation to continue.") It can flag severity based on context and candidate response, rather than purely hardcoded limits.

### C. Adaptive Code Test Generation & Refinement
- **Concept:** The Agentic AI adjusts the difficulty of the assessment on the fly.
- **Agent Action:** As the student codes, if the agent notices they are struggling with basic syntax for 15 minutes, it can use a tool (backend API) to fetch a hint or pivot the assessment to an easier, foundational problem. Conversely, if they finish a 40-minute problem in 5 minutes, the agent generates a part 2 complication ("Now make it thread-safe").

### D. Automated Deep Grader (Agentic Code Reviewer)
- **Concept:** Going beyond basic pass/fail test cases. 
- **Agent Action:** The agent pulls the submitted code, runs static analysis, evaluates Big-O complexity, variable naming conventions, and edge-case handling. It writes a complete feedback document autonomously for the mentor.

## 2. Proposed Architecture for Agentic AI

To implement this without breaking the existing monolithic flow, we should introduce an **Event-Driven Agent Loop** on the backend.

### Backend Infrastructure (FastAPI)
1. **Agent Router (`routes/agent.py`):** Dedicated endpoints for the frontend to communicate with the Agentic service.
2. **LangChain/LlamaIndex Integration:** To manage agent state, tools, and prompts.
3. **Tools for the Agent:**
   - `get_submission(submission_id)`
   - `run_code(code, lang)`
   - `create_followup_question(context)`
   - `log_proctoring_violation(severity, reason)`
4. **WebSocket Integration:** Use the existing `socketio` setup in [main.py](file:///g:/Project%20Research/virtusa/mentor-hub-fastapi/backend/main.py) so the Agent can asynchronously push events to the frontend (e.g., triggering the Dynamic Interview modal).

### Frontend Enhancements (React)
1. **Agentic Overlay Component:** A global, non-intrusive chat head or modal (`<AgentOverlay />`) that can pop up during or after the assessment to ask questions or verify proctoring flags.
2. **ProctoredCodeEditor Updates:** Pass keystroke analytics and pause/resume capabilities to the Agent, allowing the Agent to pause the timer if an intervention is required.
